# ConnectMe — Описание сервисов

## Обзор системы

ConnectMe — микросервисная система для знакомств для осознанных пользователей.

---

## 1. Telegram Bot Service

**Назначение:** Основной интерфейс взаимодействия с пользователями через Telegram.

**Функции:**
- Приём и отправка сообщений
- Рендеринг inline-клавиатур с кнопками действий
- Обработка медиа-контента (фотографии)
- Управление сессиями пользователей
- Отправка уведомлений о мэтчах и сообщениях

**Технологии:**
- Python 3.11+
- aiogram 3.x (асинхронный фреймворк для Telegram Bot API)
- aiohttp (для HTTP-запросов к Backend API)

**Взаимодействие:**
- → Backend API (REST): получение данных профиля, отправка действий (лайк/пропуск)
- → RabbitMQ (опционально): прямая публикация событий
- ← Backend API: получение анкет, мэтчей, сообщений
- ← Telegram: команды и сообщения пользователей

**Порты:** Не требуется (long-polling или webhook от Telegram)

---

## 2. Backend API (API Gateway)

**Назначение:** Единая точка входа для всех клиентских запросов, оркестрация сервисов.

**Функции:**
- Маршрутизация запросов к соответствующим сервисам
- Аутентификация и авторизация (по Telegram ID)
- Агрегация данных из нескольких сервисов
- Валидация входных данных
- Rate limiting
- Логирование запросов

**Технологии:**
- Python 3.11+
- FastAPI (асинхронный веб-фреймворк)
- Pydantic (валидация данных)
- JWT / Session-based auth
- Uvicorn (ASGI сервер)

**Взаимодействие:**
- ← Telegram Bot Service: входящие запросы
- → Profile Service: CRUD профилей
- → Matching Service: получение анкет, лайки
- → Chat Service: сообщения, мэтчи
- → Rating Service: расчёт рейтингов
- → Media Service: загрузка/получение фото
- → PostgreSQL: прямые запросы (опционально)
- → Redis: кэширование

**Порты:** `8000` (HTTP)

---

## 3. Profile Service

**Назначение:** Управление профилями пользователей (CRUD операции).

**Функции:**
- Создание профиля при регистрации (`/start`)
- Чтение профиля (просмотр своей анкеты)
- Обновление профиля (редактирование данных)
- Удаление профиля (деактивация)
- Управление интересами (JSONB)
- Геолокация (широта/долгота)
- Проверка соответствия предпочтениям

**Технологии:**
- Python 3.11+
- FastAPI
- SQLAlchemy / asyncpg (PostgreSQL driver)
- PostgreSQL (JSONB для интересов)

**Взаимодействие:**
- ← Backend API: запросы на CRUD
- → PostgreSQL: чтение/запись профилей
- → Rating Service: уведомление об обновлении профиля (для пересчёта рейтинга)
- → Media Service: связь с фотографиями

**Порты:** `8001` (HTTP)

**Таблицы:** `users`, `profiles`, `photos`

---

## 4. Matching Service

**Назначение:** Алгоритмы подбора и ранжирования анкет, обработка свайпов.

**Функции:**
- Подбор анкет по фильтрам (пол, возраст, геолокация, предпочтения)
- Ранжирование по комбинированному рейтингу
- Кэширование 10 анкет в Redis на сессию
- Обработка лайков и пропусков
- Создание мэтчей при взаимных лайках
- Публикация событий в RabbitMQ

**Технологии:**
- Python 3.11+
- FastAPI
- Redis (кэширование списков анкет)
- PostgreSQL (гео-запросы через PostGIS)
- RabbitMQ (публикация событий)

**Взаимодействие:**
- ← Backend API: запросы на подбор анкет, лайки
- → PostgreSQL: чтение профилей, запись свайпов
- → Redis: кэш анкет (`ranked_profiles:{user_id}:{session_id}`)
- → RabbitMQ: публикация в `swipe_events`, `match_events`
- → Rating Service: запрос рейтингов
- → Chat Service: создание чата при мэтче

**Порты:** `8002` (HTTP)

**Таблицы:** `swipes`, `matches`

---

## 5. Chat Service

**Назначение:** Обмен сообщениями между пользователями с активным мэтчем.

**Функции:**
- Отправка текстовых сообщений
- Отправка фотографий
- Статус прочтения сообщений
- WebSocket для реального времени (опционально)
- История переписки

**Технологии:**
- Python 3.11+
- FastAPI
- WebSockets (для real-time)
- RabbitMQ (брокер сообщений)

**Взаимодействие:**
- ← Backend API: запросы на отправку/получение сообщений
- ← Telegram Bot Service: уведомления о новых сообщениях
- → PostgreSQL: сохранение сообщений
- → RabbitMQ: подписка на `chat_messages`, публикация событий
- → Match Service: проверка активности мэтча

**Порты:** `8003` (HTTP + WebSocket)

**Таблицы:** `messages`

---

## 6. Rating Service

**Назначение:** Расчёт и обновление многоуровневых рейтингов пользователей.

**Функции:**
- **Первичный рейтинг:**
  - Полнота анкеты (30%)
  - Качество фото (30%)
  - Соответствие предпочтениям (20%)
  - Верификация (20%)
- **Поведенческий рейтинг:**
  - Количество лайков (25%)
  - Ratio лайков/пропусков (25%)
  - Частота мэтчей (20%)
  - Инициирование диалогов (15%)
  - Паттерны активности (15%)
- **Комбинированный рейтинг:**
  - Формула: `combined = (primary * 0.4) + (behavioral * 0.4) + (referral_bonus * 0.2)`

**Технологии:**
- Python 3.11+
- Celery (асинхронные задачи)
- PostgreSQL (хранение рейтингов)
- Redis (брокер для Celery)

**Взаимодействие:**
- ← RabbitMQ: события `rating_updates`
- ← Profile Service: уведомления об обновлении профиля
- ← Matching Service: запросы на расчёт рейтинга
- → PostgreSQL: чтение/запись рейтингов
- → Celery: запланированные задачи (daily recalculation)

**Порты:** Не требуется (Celery worker)

**Таблицы:** `ratings`

---



**Функции:**
- Хранение базы вопросов по категориям
- Категории: `general`, `hobbies`, `travel`, `food`, `entertainment`, `deep`
- Уровни сложности: `light`, `medium`, `deep`
- Подбор случайного вопроса с учётом:
  - Категории (приоритет по интересам пользователя)
  - Уровня сложности (адаптивный подбор)
  - Частоты использования (избегать повторений)
  - Success rate (предпочтение успешным вопросам)
- Отслеживание статистики использования
- A/B тестирование вопросов

**Технологии:**
- Python 3.11+
- FastAPI
- PostgreSQL (хранение вопросов и статистики)
- Random selection с весами

**Взаимодействие:**
- ← Chat Service: вставка вопроса в сообщение
- → PostgreSQL: чтение вопросов, запись статистики
- → Analytics: данные об эффективности вопросов

**Порты:** `8004` (HTTP)


---

## 7. Media Service

**Назначение:** Загрузка, хранение и выдача медиа-контента.

**Функции:**
- Загрузка фотографий профилей
- Генерация превью (thumbnails)
- Валидация формата и размера
- Управление бакетами Minio
- Генерация presigned URLs для доступа
- Удаление медиа

**Технологии:**
- Python 3.11+
- FastAPI
- Minio SDK (S3-compatible)
- Pillow (обработка изображений)

**Взаимодействие:**
- ← Backend API: запросы на загрузку/получение фото
- ← Profile Service: привязка фото к профилю
- → Minio: загрузка/чтение/удаление объектов
- → PostgreSQL: метаданные фото (s3_key, bucket, order)

**Порты:** `8004` (HTTP)

**Buckets:**
- `profile-photos` (private) — фотографии профилей

---

## 8. PostgreSQL

**Назначение:** Основное хранилище структурированных данных.

**Функции:**
- Хранение всех сущностей (пользователи, профили, свайпы, мэтчи, сообщения, вопросы)
- Транзакционная целостность
- Гео-запросы (PostGIS для подбора по локации)
- JSONB для гибких полей (интересы, предпочтения)

**Технологии:**
- PostgreSQL 15+
- PostGIS (гео-расширение)
- pgBouncer (connection pooling)

**Таблицы:**
- `users` — базовые данные Telegram
- `profiles` — расширенные профили
- `photos` — метаданные фотографий
- `swipes` — история лайков/пропусков
- `matches` — взаимные лайки
- `messages` — сообщения чата
- `ratings` — рейтинги пользователей
- `date_ideas` — идеи для свиданий

**Порты:** `5432`

---

## 9. Redis

**Назначение:** Кэширование и брокер для Celery.

**Функции:**
- Кэширование 10 анкет на сессию (`ranked_profiles:{user_id}:{session_id}`)
- Сессионные данные пользователей
- Rate limiting
- Брокер сообщений для Celery
- TTL для временных данных

**Технологии:**
- Redis 7+
- Redis Streams (опционально для событий)

**Ключи:**
- `ranked_profiles:{user_id}:{session_id}` — кэш анкет
- `session:{telegram_id}` — данные сессии
- `ratelimit:{telegram_id}:{action}` — rate limiting
- `celery:*` — задачи Celery

**Порты:** `6379`

---

## 10. RabbitMQ

**Назначение:** Асинхронная обработка событий между сервисами.

**Функции:**
- Публикация событий свайпов
- Уведомления о мэтчах
- Обновления рейтингов
- Сообщения чата

**Технологии:**
- RabbitMQ 3.12+
- Management Plugin (мониторинг)

**Exchanges:**
| Name | Type | Description |
|------|------|-------------|
| `swipe_events` | direct | События лайков и пропусков |
| `match_events` | direct | События создания мэтчей |
| `rating_updates` | fanout | События обновления рейтингов |
| `chat_messages` | direct | Сообщения чата между пользователями |

**Порты:** `5672` (AMQP), `15672` (Management UI)

---

## 11. Celery Worker

**Назначение:** Фоновые и запланированные задачи.

**Функции:**
- **Ежедневные задачи:**
  - `rating_recalculation` — пересчёт комбинированных рейтингов
  - `analytics_aggregation` — агрегация метрик
- **Ежечасные задачи:**
  - `cleanup_expired_sessions` — очистка устаревших сессий в Redis
- **Событийные задачи:**
  - Обработка событий из RabbitMQ
  - Уведомления пользователям

**Технологии:**
- Python 3.11+
- Celery 5.x
- Redis (брокер и бэкенд результатов)

**Взаимодействие:**
- → Redis: получение задач, сохранение результатов
- → PostgreSQL: обновление рейтингов, аналитика
- → RabbitMQ: подписка на события

**Порты:** Не требуется (worker process)

---

**Функции:**
- Хранение фотографий профилей

**Технологии:**
- Minio (self-hosted S3)

**Buckets:**
| Bucket | Access | Description |
|--------|--------|-------------|
| `profile-photos` | private | Фотографии профилей |

---

## 13. Metrics & Monitoring

**Назначение:** Сбор и визуализация метрик системы.

**Функции:**
- Сбор метрик со всех сервисов
- Визуализация (Grafana)
- Алертинг при превышении порогов

**Метрики:**
- `total_users` — общее количество пользователей
- `active_users_daily` — ежедневная активность
- `swipes_per_hour` — свайпов в час
- `matches_per_day` — мэтчей в день
- `message_exchange_rate` — обмен сообщениями
- `cache_hit_rate` — эффективность кэша (цель: >90%)
- `queue_message_lag` — задержка очередей
- `api_response_time_p95` — время ответа API (цель: <500ms)
- `error_rate` — процент ошибок

**Технологии:**
- Prometheus (сбор метрик)
- Grafana (визуализация)
- Loki (логи)

**Порты:** `9090` (Prometheus), `3000` (Grafana)
